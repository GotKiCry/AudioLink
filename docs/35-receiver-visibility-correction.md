# 更正 · 「接收端看不见发起端」是测试时序造成的假象（附桌面音量 IPC）

> 日期 **2026-09-16**。本轮的主线是**复核上一轮记下的疑点** —— 结论是：那不是产品缺陷，
> 是我把断言写在了错误的位置。文档里留着一个假缺陷比没有记录更坏，所以这一轮专门来更正它。

---

## 1. 更正的结论

上一轮（docs/33 §4）我写下：**接收端的 peers() 里查不到发起端**，并把它列为待核疑点。

**复核：断言写在 shutdown 之后造成的假象。** 按时序采样（0.5 s / 2 s / 3.5 s / 5 s）看到的
是：链路上对端表一直是 **1 条会话**、状态在 Streaming/Degraded、遥测有值；只有**关闭之后**才变 0 ——
那是正常清理，不是缺陷。

## 3. 教训（写下来，因为它是同一类错误）

**断言的位置本身就是结论的一部分**：在 shutdown 之后查表、在渐变期测稳态、在 priming 前量队列 ——
都是把「测量时机」当成了「被测对象的性质」。本仓库已经因为同类错误栽过三次（本轮 + 音量渐变期 + 首轮队列水位）。

上一轮的 SET_GAIN 只在引擎里生效；本轮把它通到外壳（UI 滑块下一轮做）：
