# M4 · 多路混音的对齐观测（以及一个诚实的缺口）

> 日期 **2026-09-16**。M4 交付物 5 是「多路时钟对齐：不同源的流按各自 epoch 换算到本地时钟后再混音」。
> 这一轮把**能观测的部分**做完，并把**做不到的部分**明确立项 —— 后者比前者更重要。

## 1. 交付物：混音观测（看得见）

| 层 | 内容 | 位置 |

| 引擎 | Engine::mixer_stats() -> Option<MixSnapshot>：无混音器时 None，有则给出源数 / 帧数 / 掉队帧 / 限幅样本 | core/crates/audiolink-engine/src/runtime.rs |

**掉队帧（partial_frames）就是「对齐好不好」最直接的读数**：两路都持续供帧时它应当长期为 0；
某一路开始掉队，它会立刻涨起来 —— 这比"听起来有没有问题"可靠得多。

那条实测数据（298 帧里只有 1 帧是单路）说明：稳态下两路都在稳定供帧，混音**不是靠补静音撑场面**。

## 2. 诚实的缺口：多源之间没有共同时间基准

协议 §7 的 epoch 是「**发送端**指定、接收端排播」。而 M4 的拓扑（2 部手机 → 1 台 PC）里，
两个发送端是两个独立的源，它们各自的采集时间轴不同 —— 当前实现里：

| 能力 | 现状 |
|---|---|
| 每条接收会话各自按 epoch 排播 | ✅ 已实现（docs/28、docs/29） |
| 同一发送端 → 多台接收端对齐 | ✅ 已实现（同一 epoch 广播给成员） |
| **多个发送端之间**采样级对齐 | ❌ **未实现** —— 缺少一个平级的基准来源 |

要做到第三点，需要两件新东西：

1. **接收端（PC）作为基准来源**：由它广播 epoch 给所有发送端，而不是只能由发送端指定；
2. **发送端的「预约发送」**：发送端把 epoch 用在自己的**发送时间轴**上（sample_index 的 0 点
   对齐到 epoch），而不是从自己启流的瞬间开始计数。

这两件都不在本轮范围内，已经作为独立待办立项（见面板），而不是塞进文档角落。
