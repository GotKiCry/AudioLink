# M3 · 每会话独立音量（SET_GAIN / SET_MUTE 接线）

> 日期 **2026-09-16**。M3 交付物 1 写的是「发送端并行推流（≥ 8 目标），**每会话独立统计与音量**」。
> 上一轮把「并行推流」的结构做完了（共享采集枢纽），这一轮把「独立音量」接上。

---

## 1. 交付物

| 层 | 内容 | 位置 |
|---|---|---|
| 纯逻辑 | GainState：当前值 → 目标值按步长逐帧逼近；f32 增益 → 千分点整数（内部一律整数比较，浮点不可复现） | core/crates/audiolink-engine/src/gain.rs |
| 校验 | NaN / inf / 负数 / 超上限（§4.1 的 0.0–2.0）一律拒绝，**绝不静默夹到合法值再假装成功** | 同上 |
| 播放侧 | 每帧写前取一次增益并乘到样本上；每帧最多走一个步长（硬切增益就是爆音） | runtime.rs（playout_main） |
| 每会话 | 增益状态挂在**播放句柄**上 —— 每会话一份，多会话各调各的，而采样时间轴仍然共享 | 同上 |
| 接线 | ControlRequest::SetGain / SetMute 从「明确不做」变成真的生效；stream_id 校验（指向别的流则忽略） | 同上 |
| API | Engine::set_peer_gain(peer, gain, ramp_ms)：**发送端**调接收端音量；非法值在发送端就拒绝，不发到线上 | 同上 |

SET_MUTE 用 50 ms 渐变（静音/恢复都不该有咔哒声）；SET_GAIN 用协议给的 ramp_ms。

---

## 2. 一个被兑现很久的承诺

runtime 里原来有这么一段注释（大意）：**「假装接受了 SET_GAIN，用户会以为音量真的变了，
然后来查为什么调音量没用」**。所以此前 SET_GAIN 是「明确不做」而不是「假装做了」。
这一轮把它变成真的：参数严格校验、渐变落地到样本、每会话独立。

---

## 3. 验证

| 层 | 内容 |
|---|---|
| 纯逻辑单测 | **8 项**：起步夹取与已到位、按窗口分步（20 ms 帧 / 100 ms 渐变 = 每帧 200 千分点）、零渐变一帧到位、极小差值仍有步长、静音→恢复往返、超上限拒绝且状态不变、协议浮点严格转换（NaN / inf / 负数 / 2.5 全拒）、放大到 2.0 |
| 端到端 | tests/gain_control.rs（真 QUIC + 真 PIN + 记录写出的 PCM）：基线 RMS **0.1772** → 下发静音后 **0.0000** → 恢复后 **0.1773**；越界增益（3.0）在发送端返回 Err |
| 诊断细节 | 测试最初把「渐变期」也算进稳态窗口（RMS 0.0274），改成先丢掉过渡段再测稳态 —— 现在数字干净得起鸡皮疙瘩 |
| 回归 | 引擎 142 单测 + 全部集成测试（含 multi_session / gain_control）、桌面全量、内核与桌面 clippy、fmt 全绿 |
