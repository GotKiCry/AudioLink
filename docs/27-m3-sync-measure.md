## 2. 设计取舍

### 2.1 量具本身先被量一遍

真值（4.7 ms 固定偏差 + 120 ppm 漂移）是**可以合成**的，所以没有理由不合成：自检逐对比较真值，
单对最大误差必须 < 0.05 ms、漂移误差 < 10 ppm。本轮实测 **0.010 ms / 1.0 ppm**。
只有它能过，这些数字才配拿去量真机。

### 2.2 踩到的坑：单一频率的长正弦会让互相关产生周期歧义（实测）

第一版夹具用 1 kHz 正弦脉冲，测出来的偏差**散开约 1 ms** —— 不是噪声，是互相关的**隔壁峰**：
正弦的自相关在 lag 差一个周期（48 采样 = 1 ms）时同样高，搜索会落到隔壁峰上。处置两条：

1. 夹具与自检改用**宽带噪声突发**（0.4 ms 指数衰减）：自相关只有一个尖峰。现实里的 click、音乐里的瞬态也是这个形状；
2. 测具**不再假装没看见**：搜索范围内若存在另一个几乎等高的相关峰（≥ 最佳峰 − 0.02），该对标记 ambiguous，
   并在报告与 notes 里写明 —— 偏差可能落在隔壁周期上，用户必须知道。

> 结论：真机验收请用**宽带 click**（或音乐里的瞬态），不要用单一频率的长正弦。

### 2.3 不做重采样

两段录音采样率不一致**直接报错**（错误文本提示先统一）。测具只该测设备偏差，不该把自己重采样器的误差算进去。

### 2.4 测具撒谎比测不出更坏

静音、纯直流、检测不到脉冲、脉冲不足 2 个、波形对不上（NCC < 0.5）一律**明确报错**（退出码 3），
绝不返回一个看起来正常的「0 偏差、验收通过」。单测里有一条负向用例：A 是脉冲串、B 是等长的伪随机噪声
→ 必须报 NoPulses 或 NotEnoughPulses。

### 2.5 WAV 自研解析

与 pcap 同一口径：不引第三方库。支持 EXTENSIBLE（解出 SubFormat 里的有效编码）、24-bit、
奇数长度块的填充字节、data 块写入中途断掉的容错（按整帧截断）；拒绝非 RIFF / 缺 fmt / 缺 data / 不支持的位深。

### 2.6 符号约定与「判据必须与漂移一致」

偏差为正 = B 比 A 晚；漂移为正 = B 的时钟比 A 快（对「A 侧时刻 → 偏差」做线性回归的斜率，ppm）。
自检最初拿**偏差均值**去比固定偏差，于是永久带着 漂移 × 平均时刻 这一项系统误差（本轮被咬过一次），
改成**逐对比较真值**后才干净。

    自检：配对 6 对（a=6 / b=6 个脉冲）
      真值 偏差 +4.700 ms / 漂移 +120.0 ppm
      量出 偏差 +4.847 ms / 漂移 +119.0 ppm（P95 5.000 ms）

    漂移 +119.0 ppm（正 = B 比 A 快）
    判定 within（门限 ±10.000 ms / ±200.0 ppm）

## 4. 真机验收怎么用（M3 的 ±10 ms）

1. 两台接收端加入同一个同步组（或手工同时起播），播放同一条含**宽带 click** 的测试轨（建议间隔 500 ms、至少 6 个）；
2. 各自录下自己的输出（线路录制最干净），导出 WAV，采样率统一到 48 kHz；
3. 跑：sync-measure phone-a.wav phone-b.wav --json target/evidence/sync/m3.json
4. 判据：verdict = within（|均值| 与 P95 都 ≤ 10 ms、漂移 ≤ 200 ppm）。
   偏差偏大时看逐对偏差有没有趋势：**有趋势** = 晶振速率差（后续要靠 drift_ppm 做速率微调）；
   **没有趋势** = 固定延迟差（后续要靠每设备手动延迟补偿）。
