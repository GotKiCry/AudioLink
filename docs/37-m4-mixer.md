## 1. 交付物

| 层 | 内容 | 位置 |
|---|---|---|
| 纯逻辑 | PcmMixer：多路求和、软限幅（拐点以上指数逼近 ±1）、每路增益/静音、缓冲满丢最旧、上限 8 路 | core/crates/audiolink-audio/src/mixer.rs |
| 可观测 | 每次混音返回 MixStats（参与路数 / 被限幅样本数 / 限幅前峰值）+ 累计限幅计数 | 同上 |
| 引擎接线 | 引擎级混音器（第一个接收会话是 **owner**，真正打开设备；其余会话把帧混进来） | core/crates/audiolink-engine/src/runtime.rs |
| 每路增益 | SET_GAIN 落到**本会话那条混音输入**上（多会话各调各的） | 同上 |
| 生命周期 | 会话停止时把自己的源从混音器摘掉（否则重连几次就会撞上 8 路上限） | 同上 |
| 上限 | 超过 FR-12 的 8 路 → 明确报 STREAM_LIMIT，而不是悄悄丢掉一路 | 同上 |

**关键设计：owner 模式。** 同一台接收端只打开一次播放设备；第一个会话是 owner，它的播放线程
照旧跑 M1/M2 的全套调度（抖动深度、欠载补静音、迟到丢弃、§7 排播），只是**写出去的内容**从
「自己那一帧」变成「混音器的输出」；其余会话继续跑自己的调度，只把帧**混进去**、不碰设备。

这样做的原因很直接：M1/M2 的播放纪律是花了三轮调出来的，混音不该把它推倒重来 ——
只换「写什么」，不换「什么时候写」。

## 2. 验证

| 层 | 内容 |
|---|---|
| 单测（mixer） | **11 项**：单路直通、两路求和、每路增益与静音、第 9 路拒绝、重复/未知源、非整帧拒绝、空源按静音补而不重复、软限幅把 1.8 压回 1.0 以内并计数、缓冲满丢最旧、移除后不再贡献、格式自持 |
| 端到端 | tests/mixer_convergence.rs：**两个发送端 → 一个接收端**（真 QUIC + 真 PIN + 记录写出的 PCM）。两路混音 RMS **0.2501** → 把 A 路静音后 **0.1769** |
| 那条数字的意义 | 0.1769 / 0.2501 = **0.707 ≈ 1/√2** —— 两路**不相关**信号去掉一路，功率正好减半、幅度正好降到 1/√2。这不是巧合，是「两路都真的进了输出」的定量证据 |
| 回归 | 引擎 142 单测 + 全部集成测试（含 multi_session / gain_control）、桌面全量、两边 clippy、fmt、前端 build 全绿 |
