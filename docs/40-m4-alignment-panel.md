# M4 · 桌面「多源对齐」面板

> 日期 **2026-09-16**。一句话：把内核里那个「用同一个现在推算两路编号的跨度」搬到界面上 ——
> 多源混音出错时耳朵听到的是回声，这块面板告诉你**差了多少毫秒**。

---

## 1. 面板要回答什么

M4 的前两步已经做完：

1. **接收端广播共同基准**（`RECEIVER_EPOCH`，`0x44`）—— 让两台发送端有同一个时间原点；
2. **直接读数**（`Engine::stream_axes()`）—— 每路「最近一帧编号 ↔ 到达时刻」。

缺的是把它变成**人能看的**：调音的时候没人会去读 `stream_axes` 的返回值。

## 2. 数据链路（一条直线，没有中间状态）

```text
音频数据报到达（每包一次 64 位原子写，不加锁不分配）
   ↓  Engine::stream_axes()  +  Engine::monotonic_ms()
alignment_view(axes, now_ms)   ← 纯函数（view.rs，可单测）
   ↓  Tauri command `alignment`
前端 useState  ←  1 Hz 轮询（不是事件驱动）
```

**为什么是 1 Hz 轮询**：读数在引擎里**每包**都在变（50 包/秒 × 路数），事件驱动会变成「每包一次 IPC」，
而界面只需要看趋势。判据本身（跨度）也是稳态量 —— 一帧 20 ms，看一秒一次足够。
没有对端时定时器不启动（不空转）。

## 3. 判据与阈值

| 结论 | 条件 | 含义 |
|---|---|---|
| `aligned` | 跨度 ≤ 960 样本（1 帧 / 20 ms） | 采样级对齐达标：同一编号就是同一时刻的声音 |
| `drifting` | 跨度 > 960 样本 | 时间轴错位 —— 多半是没广播过共同基准，或基准没生效 |
| `unknown` | 有效读数不足两路 | 还没开始收音频，或只有一路在流 |

阈值取「一帧」是刻意的：混音器按帧对齐，**一帧以内**的偏差在混音上已经听不出来；
而 M4 实测的对齐结果是 144 样本（3 ms），离阈值还有 6 倍余量。

## 4. 测试

`alignment_view` 是纯函数，单测 5 项（`desktop/src-tauri/src/view.rs`）：

| 用例 | 断言 |
|---|---|
| 单路 | `Unknown`，跨度 `None`（**不给数字**：一路无法比较） |
| 两路差 144 样本 | `Aligned`，跨度 144 样本 / 3 ms |
| 两路差 72 048 样本 | `Drifting`，跨度 72 048 样本 / 1 501 ms |
| 两路都没收到音频 | `Unknown` |
| 一路上有一路无 | `Unknown`（**不**用单路硬凑一个跨度） |

前端由 `tsc --noEmit`（严格）+ `vite build` 把关。

## 5. 已知缺口

- **真机场景未验**：需要手机与 PC 同时推流（当前 `192.168.31.x` vs `192.168.3.x`，不可达）；
- 面板只显示「当前跨度」，没有历史趋势（M2 的遥测面板已经给了曲线能力，将来可复用）；
- 没有「一键广播基准」按钮 —— 目前 `broadcast_epoch` 只能从引擎 API 调（真机联调时需要一个入口）。

---

## 6. 「广播共同基准」入口（2026-09-16 第二轮）

§5 记的第三条缺口（没有入口，只能从引擎 API 调）这一轮补上：

| 层 | 动作 |
|---|---|
| 引擎 | `Engine::broadcast_epoch(lead_ms)`（上一轮已有） |
| 命令 | Tauri `broadcast_epoch(lead_ms) -> u32`（返回发出的会话数） |
| 前端 | 面板上的「广播共同基准」按钮 + 提前量输入（**默认 200 ms**） |

**为什么提前量默认给宽（200 ms）**：发送端收到基准后会**等到那个时刻**才从编号 0 开始发。
提前量太小，还没等到就已经过去了（那一段采集会被整段丢掉）；太大只是让大家多等一会。
两种错法的代价不对称 —— 所以默认取宽的那边。

**这个按钮只能由接收端按**，这不是 UI 约定而是事实：`broadcast_epoch` 的语义就是
「我（混音方）指定共同原点」。发送端按它没有意义 —— 它正是要被对齐的那一方。

成功后提示「已向 N 条会话广播共同基准（提前量 X ms）」；没有已连接对端时引擎会拒绝，
错误原因原样显示（人话映射在错误层，不在组件里）。
