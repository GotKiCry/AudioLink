# 故障排查

> 下面每一条都来自这个项目**真实踩过的坑**。动手之前先看 §1：日志在哪、要附什么材料。
> English version: [`troubleshooting.en-US.md`](troubleshooting.en-US.md)

---

## 1. 日志与配置在哪（先看这里）

```text
%APPDATA%\com.gotkicry.audiolink\
```

里面有 `settings.json`（语言/自启/上次设备）、`trust.json`（配对白名单）、`identity\`（本机证书与私钥）、
`.window-state.json`（窗口位置）与日志。

**提交问题时请带上**：① 版本号（「关于」面板）；② 日志文件；③ 两台设备各自地址的**前三段**；
④ 网络形态（有线 / Wi-Fi / 热点）；⑤ 遥测面板截图或导出的 CSV。缺了这些只能靠猜。

## 2. 找不到设备 / 连不上（最常见）

| 可能原因 | 怎么确认 | 怎么办 |
|---|---|---|
| **两台设备不在同一网段** | 比地址前三段：`192.168.3.x` 与 `192.168.31.x` 就是**两个网段** | 让它们接同一个路由器；跨网段既发现不到、直连也不通（这是本项目真遇到过的形态：手机 `192.168.31.231`、PC `192.168.3.200`，互 ping 100% 丢包） |
| **AP 客户端隔离**（路由器/热点把同一 Wi-Fi 的设备互相隔开） | 同一 Wi-Fi 但互 ping 不通 | 关掉路由器里的「AP 隔离 / 客户端隔离」；实在关不掉时用对方「本机状态条」上的地址**手动添加**，但隔离开启时通常仍然不通 |
| **Windows 防火墙**拦住了 UDP | 第一次运行时没允许 | 在防火墙提示里勾选「专用网络」；已误点「取消」就去「允许应用通过防火墙」里加回来 |
| 手机热点 / 访客 Wi-Fi / 公司网络 | — | 这些形态常带隔离，换一个普通家用路由器试 |
| 端口被占或被策略封 | 默认端口 `58290` | 换网络试；两台设备要在同一网络里 |

## 3. 连上了但没有声音

1. 对端卡片是不是「**推送中**」？没开流就没有声音可放。
2. 音量滑块是不是 0（0–200%）？
3. **PC 采集的是哪个输出设备**：AudioLink 采集的是「某个输出设备正在播放的声音」。播放器必须把声音送到
   **同一个**设备 —— 换过默认输出设备后，回「采集声音」里点「刷新设备」并重新选择。
4. 播放器开了**独占模式**（WASAPI Exclusive）时，系统混音里没有它的声音，也就采不到 → 关掉独占。
5. 手机端：调的是**媒体音量**（不是铃声/通知音量）。

## 4. 声音断续 / 卡顿 / 杂音

- 先看遥测面板，按这个顺序读：**丢包 → 抖动 P95 → 缓冲水位 → 欠载**；
- 2.4 GHz 拥挤是常态 → 换 5 GHz，或把两端接到同一台路由器；
- 缓冲水位长期贴上限（约 120 ms）= 网络抖动大；欠载持续增长 = 链路跟不上；
- **弱网下码率会自动下降**（自适应），这是设计，不是故障；
- 蓝牙耳机在系统层会额外引入 100–200 ms 延迟，与 AudioLink 无关。

## 5. 手机端

| 现象 | 原因与处理 |
|---|---|
| `adb install` 报 **-99**（MIUI/HyperOS） | 开发者选项里打开「**USB 安装**」（部分版本叫「通过 USB 安装应用」），打开后重新安装 |
| 提示「应用未安装」 | 装错了 ABI：32 位机器需要 `armeabi-v7a` 包，绝大多数现代手机用 `arm64-v8a` 包 |
| 后台被杀、声音断掉 | 省电策略里把 AudioLink 加入白名单；用前台服务通知确认它还在跑 |
| 想让手机**采集**系统声音 | ~~尚未实现（见用户手册 §13），当前 Android 以接收播放为主~~ **已实现**（由 M4 能力位轮次 `a0158a2` 落地：内录走 MediaProjection + AudioPlaybackCapture，需 Android 10+；麦克风走 AudioRecord。详情见用户手册 §13）——**真机验收未完成** |

## 6. PC 端

| 现象 | 说明 |
|---|---|
| 关掉窗口但程序没退出 | **这是设计**：AudioLink 常驻托盘（可能还在给别的房间送声音）。右键托盘图标 → 退出 |
| 安装时 SmartScreen 警告 | 安装包**未做代码签名**（见 [`docs/42`](../42-m5-release-pipeline.md) §2.2）；选「更多信息 → 仍要运行」 |
| 绿色版提示缺少 WebView2 | 装一次「Microsoft Edge WebView2 Runtime」（Windows 11 自带） |
| 开机自启不生效 | ① 系统「启动应用」里被禁用；② 用了绿色版并**移动过目录** —— 自启登记的是当时的 exe 路径，移动后回设置里重新开关一次 |

## 7. 更新

- **应用内自动更新失败**：需要发布方在 Release 里提供 `latest.json` 与 `.sig` 签名（缺任一项则客户端不会更新）；
  另外客户端必须能访问 GitHub（公司网络/代理可能拦）。
- **手动更新**：安装版直接装新版覆盖（配置保留）；绿色版关掉程序后替换 exe 即可。
- **更新后配对白名单会丢吗**：不会，配置在用户目录（§1），与安装形态无关。

---

## 8. 已知限制（不是 bug，别当成故障排查）

- 跨网段、跨公网不通 —— 明确不做（只在局域网工作）；
- 安装包未签名，首次运行有 SmartScreen 提示；
- 不支持 iOS 与 Web 端；
- Windows 端采集的是**输出设备的整体混音**，不能只采某个应用的声音；
- 绿色版没有应用内自动更新（手动替换 exe）。
