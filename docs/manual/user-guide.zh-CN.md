# AudioLink 用户手册

> 面向**使用者**。想改代码请看 [`CONTRIBUTING.md`](../../CONTRIBUTING.md)；设计细节在 [`docs/`](../)。
> English version: [`user-guide.en-US.md`](user-guide.en-US.md)

---

## 1. 这是什么

AudioLink 把一台设备上正在播放的声音，低延迟地送到同一局域网里的其他设备 —— 电脑 ⇄ 手机双向，
可以同时送给多台，也可以让多台的声音混在一起放出来。

**只在局域网内工作**：不经过任何服务器，不上传音频内容，不采集遥测到云端。

---

## 2. 先装哪个

| 形态 | 适合谁 | 差异 |
|---|---|---|
| **Windows 安装包**（`AudioLink_*_x64-setup.exe`） | 大多数 PC 用户 | 装进系统、有开始菜单与卸载入口、支持**应用内自动更新** |
| **绿色版**（`AudioLink_*_x64_portable.zip`） | 不想安装 / 放在 U 盘里 | 解压即用、删目录即卸载；更新靠手动换 exe；没有自动更新 |
| **Android APK** | 手机 / 平板 | 分两个包：`arm64-v8a`（绝大多数手机）与 `armeabi-v7a`（较老的 32 位机器）—— 装错会提示「应用未安装」 |

> 绿色版需要 **WebView2**：Windows 11 自带；Windows 10 若提示缺少，装一次
> 「Microsoft Edge WebView2 Runtime」即可（安装包里同样带这个检测）。

---

## 3. 第一次用：三步

1. **让两台设备在同一个局域网**（同一个 Wi-Fi，或同一台路由器下的有线网络）。
2. **在 PC 上连接对方**：主界面的「手动添加设备」里填对方的地址（形如 `192.168.1.23` 或
   `192.168.1.23:58290`）。手机端不用填 —— 连接由一端发起。
3. **配对**：一端屏幕会显示 6 位数字，在另一端输入它。两侧显示一致，说明中间没有第三台设备。

配对成功后，这台设备会进入白名单 —— 以后再连不需要重新输码。

---

## 4. 推流与接收

| 想做的事 | 怎么做 |
|---|---|
| 把本机声音送出去 | 在对端卡片上点「开始推流」 |
| 停止 | 同一张卡片上的「停止推流」 |
| 调对方的音量 | 卡片上的音量滑块（0–200%），拖动后约 200 ms 渐变成效 |
| 同时送多台 | 每张卡片各自「开始推流」；采集只做一次，几台接收端共享同一路声音 |
| 接收别人的声音 | 不需要操作：对方开流后本机自动开始播放 |

---

## 5. 声音从哪来（Windows 采集）

顶部「采集声音」里选的是**输出设备**（扬声器 / 耳机 / 虚拟声卡）——AudioLink 采集的是「这台设备正在播放的声音」。

- 「系统默认（开始推流时使用）」= 跟着 Windows 当前默认输出设备走；
- 播放器必须把声音送到**同一个**设备，否则采集到的就是静音（例如播放器走了独占模式，或指定了另一块声卡）；
- 「切换音源前请先停止推流」：推流中不允许换设备，因为换源会让对端听到一段错位的声音；
- 换了耳机/声卡之后点「刷新设备」重新枚举。

## 6. 设置

| 设置 | 作用 |
|---|---|
| **界面语言** | 中文 / English，立即生效，跨重启保留 |
| **开机自动启动** | 随 Windows 登录启动 |
| **启动时自动连接上次设备** | 只记得**成功连接过**的地址；连不上时不会弹错误，只在状态条给一句提示 |

**关掉窗口程序不会退出** —— AudioLink 常驻系统托盘（这是设计：它可能在给别的房间送声音）。
要真正退出：右键托盘图标 → 退出。

## 7. 同步组与多源对齐（进阶）

**同步组**：在一台发送端上勾选几台设备 → 「建组」。组内各接收端会在同一个约定时刻开始播放，
而不是各自收到就放 —— 这样多房间听起来才是「同时」。「提前量」是这个约定时刻相对现在的提前量（默认 200 ms，
网络越差可以给越大）。

**多源对齐**：当本机同时收到几路声音（比如两部手机 → 一台 PC），「多源对齐」面板会显示每一路的
「最近编号 / 推算编号 / 到达时刻」以及当前的**跨度**（各路样本编号的差值）。
跨度 ≤ 1 帧（960 样本 / 20 ms）就是对齐了。

面板上的「广播共同基准」用于让所有发送端把编号对齐到同一个原点 —— 它只能在**混音方**按，
因为接收端才是这里的基准来源。

## 8. 看数字（遥测面板）

| 指标 | 什么意思 | 正常范围参考 |
|---|---|---|
| 端到端延迟 | 从采集到对方播放的估算延迟 | Wi-Fi 上 80–110 ms 属正常 |
| 抖动 / 抖动 P95 | 到达间隔的波动 | 越小越好；P95 明显偏大说明 Wi-Fi 不稳 |
| 丢包 | 链路层实际丢包率 | 0% 最好；应用层有冗余双发与 NACK 兜底 |
| 码率 | 实际发送码率 | 默认约 320 kbps（含冗余双发）；弱网会自动下降 |
| 缓冲水位 | 对端为抗抖动攒了多少毫秒 | 20–120 ms；长期贴上限说明网络抖动大 |
| 欠载 | 播放时没数据可放的次数 | 越少越好；持续增长说明网络或缓冲设置跟不上 |

「导出 CSV」把累积的采样点交给后端写成 CSV 文件，路径会在提示里给出 —— 排查问题时把它附上很有用。

## 9. 配置与数据放在哪

都在**用户目录**里（不在安装目录）：

```text
%APPDATA%\com.gotkicry.audiolink\
  settings.json         界面语言 / 开机自启 / 上次设备
  trust.json            已配对设备白名单
  identity\             本机自签证书与私钥（配对信任的基础）
  .window-state.json    窗口位置与大小
  日志                  排查问题时看这里
```

绿色版与安装版**共用**这份配置：装过安装版再用绿色版，设置与白名单都还在。
要彻底重来（清空配对与设置），先退出程序，再删掉整个 `com.gotkicry.audiolink` 目录。

> 删 `identity\` 等于换了一个新身份 —— 之前配对过的设备会需要重新配对。

## 10. 卸载

- **安装版**：Windows「设置 → 应用」里卸载（或开始菜单里的卸载入口）；
- **绿色版**：删掉解压出来的目录；想连配置一起清掉，再删 §9 里的用户目录；
- **Android**：长按应用图标 → 卸载。

## 13. 已做 / 没做（免得你找）

- Android 端**系统内录**与麦克风采集：**已实现**（内录需 Android 10+，走 MediaProjection + AudioPlaybackCapture；麦克风走 AudioRecord），**真机验收未完成**；
- Android 端**省电白名单引导**：**已实现**（检测 + 可操作引导，仅跳系统白名单列表，不申请敏感权限）；Android 端**开机自启有意不做** —— Android 15+ 禁止 BOOT_COMPLETED 启动 mediaPlayback 类型的前台服务，见 docs/53-m5-audit.md；
- Windows 安装包**没有代码签名**：首次运行会有 SmartScreen 提示，选「仍要运行」即可；
- **应用内更新**：电脑端与手机端都有（只在**你点击时**检查，不在后台自动下载安装）；手机端首次更新需要允许「安装未知应用」；
- 跨公网、iOS / Web 端：明确不做。

## 14. 更新

**都只在你说的时候更新** —— AudioLink 不会在后台自动下载或安装：正在推流或录音时被静默重启，是不能接受的。

**电脑端**：「软件更新」面板 → 「检查更新」→ 有新版本时点「下载并安装」。
安装会先与对端优雅收尾，然后关闭 AudioLink、启动安装器，装完自动重新打开。

**手机端**：控制台右上角「更新」→「检查更新」→「下载并安装」。

- 手机端第一次更新时，系统会问是否允许 AudioLink 安装应用 —— 允许之后回来点「继续安装」；
- 手机端只认**正式发布**的版本：新版刚构建好但还没点「发布」时，手机上仍显示已是最新；
- 手机端从**第二次**装起才会覆盖安装（Android 要求同一个签名）。

更新失败时界面会把原因说清楚（连不上 GitHub / 超时 / 安装包不对）。国内网络访问 GitHub 不稳定时，稍后重试即可。
